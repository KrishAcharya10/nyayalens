# Legal reference policy

NyayaLens is a research and decision-support tool, not a lawyer. This
policy keeps three kinds of information apart and governs the one that
is easiest to get wrong: references to law.

## Three layers, never mixed

| Layer | What it is | Example | Shown as |
|---|---|---|---|
| **Document evidence** | Text the user's document actually contains, with offsets | "The Tenant shall bear all structural repairs" (clause 5) | "The document states…" |
| **Model inference** | What a rule or model derived from that evidence | "Liability shift - review required" | "Potential issue / review required", always with evidence |
| **Legal reference** | Metadata about a real statute a domain is commonly read against | Transfer of Property Act, 1882, s.105 | "Relevant reference (unverified)"; never as a conclusion about the document |

A legal reference is never generated by a model, never used as RAG
evidence for answering a question about the user's document, and never
turned into a finding. The risk engine does not cite statutes.

In the knowledge graph (Phase 8), the pack's references appear as
`LEGAL_REFERENCE` nodes. Each one links to the document by a `RELEVANT_TO`
edge, never `APPLIES_TO`. The node text states its verification status
and says that it is not a statement that the law applies to this document.
`tests/graphSemantic.test.ts` checks both points.

## Rules for adding a reference

Code: `apps/api/src/domains/legalReferences.ts`, typed by
`LegalFrameworkRef` in `domains/registry.ts`.

1. **Only real instruments.** Record a `section` only when the maintainer
   knows it. If not, record the instrument alone.
2. **No guessing metadata.** Leave `effectiveFrom`, `effectiveTo` and
   `sourceUrl` empty unless they come from the official text. Never build
   a URL from a pattern.
3. **Verification status is mandatory.**
   - `UNVERIFIED` is the default: a real provision, recorded from the
     maintainer's knowledge, not yet checked against the official text.
   - `VERIFIED_OFFICIAL_TEXT` means a person has checked the official text
     (e.g. India Code, or the state gazette for state Acts) and recorded
     its `sourceUrl`. A test enforces that a verified reference has a
     source URL.
4. **Jurisdiction-aware.** State legislation (rent control, stamp duty)
   must carry the state in `jurisdiction.state`, and must not be attached
   to a nationwide pack as if it applied everywhere.
5. **Versioned.** `jurisdiction.referenceVersion` records when the pack's
   references were last reviewed.

## Language rules (UI, findings, answers)

Use: *potential issue, review required, potential inconsistency, relevant
clause, the document states, evidence indicates.*

Never state a definitive legal conclusion such as *is illegal, is void,
is invalid, is unenforceable, is unlawful, violates the law, must be
struck down*. The exception is a statement backed by an authoritative,
verified reference that applies to the facts and jurisdiction, and
NyayaLens does not currently make such statements. Exactly those phrases
are enforced in code (`FORBIDDEN_PHRASES` in
`apps/api/src/risk/reasonFraming.ts`): they're checked for risk reasons
and, through the `ollama` provider, for generated answers, which fall
back to quoting the document. The RAG system prompt instructs the same.
Wider wording (e.g. "you must") is a writing rule, not yet a
machine-checked one.

## Synthetic data

Synthetic documents are not real law and not real agreements. They may
contain deliberately unfair or inconsistent clauses for testing. Nothing
generated by `research/generator/` may be presented as a statement of
what the law is.
